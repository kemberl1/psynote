## 1. Реферат / Abstract

**PsyNote** — web-приложение для врачей-психиатров, автоматизирующее создание ежедневных медицинских дневников наблюдения за пациентами. Система решает реальную клиническую проблему: детский психиатр в стационаре ведёт 20–30 пациентов одновременно и тратит до 10 часов в день на заполнение шаблонной документации, вместо живого общения с детьми.

Врач проходит краткий структурированный опросник (5–10 вопросов с выпадающими списками, 2–3 минуты), после чего система на основе RAG-архитектуры (Retrieval-Augmented Generation) генерирует готовый клинический дневник в стилистике реальных документов отделения. Качество обеспечивается корпусом анонимизированных медицинских документов, векторным поиском (Qdrant) и промпт-инжинирингом с few-shot примерами.

Технический стек: Go (API-шлюз, анонимизатор с fail-closed политикой, экспорт Word/PDF, JWT/Argon2id аутентификация), Python (RAG-пайплайн: чанкинг, эмбеддинги sentence-transformers, retrieval с MMR, генерация через LLM), React 19 (фронтенд), PostgreSQL + Qdrant (хранилища), LLM API (X5/OpenRouter). Инфраструктура — Docker Compose, всё open-source.

Достигнутый результат: полноценное приложение, снижающее время написания дневника с 20 минут до 2–3 минут; многоуровневая анонимизация (словари 60 000+ имён/фамилий, regex-детекторы, LLM-NER, fail-closed валидация); необратимое обезличивание персональных данных; полная изоляция истории по врачу. Система спроектирована и реализована за 10 этапов и готова к использованию в реальном отделении.

**Ключевые слова:** RAG, анонимизация, Go, медицинская информатика, генерация документов, векторный поиск, психиатрия.

## 2. Проблематика: почему это важно

### 2.1. Рутинная боль врача

Детский врач-психиатр в стационаре ведёт одновременно **20–30 пациентов**. На каждого пациента он обязан:

- **каждый день** — заполнять дневник наблюдения (психический статус, соматика, поведение, сон, аппетит, переносимость терапии);
- **каждые ~10 дней** — оформлять расширенный осмотр совместно с заведующим отделением (диагноз, обоснование, назначения, этапный эпикриз).

Формулировки в дневниках **в значительной степени шаблонны и повторяемы**, но требуют юридически корректного, грамотного и индивидуализированного текста. Врач не может написать «всё ок» — нужна полноценная клиническая запись, соответствующая стандартам документации.

### 2.2. Квантификация проблемы

| Метрика | Значение |
|---|---|
| Пациентов одновременно | 20–30 |
| Ежедневных дневников | 20–30 в день |
| Время на один дневник (вручную) | 10–20 минут |
| Итого рутины в день | **до 10 часов** |
| Расширенных осмотров (раз в 10 дней) | 2–3 в день |
| Время на расширенный осмотр | 20–40 минут |

**Итого:** врач тратит большую часть рабочего дня не на клиническую работу, а на бумаготворчество. Время, которое могло быть отдано живому общению с маленькими пациентами и их родителями, уходит на заполнение шаблонных формулировок.

### 2.3. Решение: автоматизация через структурированный ввод + RAG

PsyNote не заменяет врача — **инструментарий** для него. Врач отвечает на 5–10 точечных вопросов (вместо свободного набора текста), а система формирует готовый дневник по реальным клиническим шаблонам отделения:

| Что измеряем | Ручной труд | С PsyNote |
|---|---|---|
| Время на ежедневный дневник | 10–20 минут | 2–3 минуты |
| Время на расширенный осмотр | 20–40 минут | 5–7 минут |
| Когнитивная нагрузка | высокая | резко снижается |
| Время на общение с пациентом | остаточное | высвобождается |

## 3. Архитектура и обоснование стека

### 3.1. Обзор: микросервисная архитектура

Система построена по **микросервисному принципу**: 3 сервиса + 3 хранилища, оркестрированных через Docker Compose.

```
┌──────────────────────────────────────────────────────────────┐
│                     Браузер врача                            │
│            React 19 + Vite + TypeScript (Vite)               │
└──────────────────────┬───────────────────────────────────────┘
                       │ REST/JSON + JWT
┌──────────────────────▼───────────────────────────────────────┐
│              Go API-Gateway + сервисы                        │
│   Auth │ Анонимизация │ Оркестрация │ Экспорт Word/PDF      │
└───┬──────────┬──────────┬──────────┬─────────────────────────┘
    │          │          │          │
    │     ┌────▼────┐  ┌──▼───┐  ┌──▼──────────┐
    │     │RAG svc  │  │LLM   │  │PostgreSQL   │
    │     │Python   │  │X5 API│  │users/history│
    │     │FastAPI  │  └──────┘  └─────────────┘
    │     └────┬────┘
    │     ┌────▼────┐
    └─────│Qdrant   │
          │векторы  │
          └─────────┘
```

| Контейнер | Технология | Ответственность |
|---|---|---|
| **Frontend** | React 19, Vite, TypeScript | Опросник, рабочая область, история, экспорт |
| **API-Gateway** | **Go** (net/http, pgx) | Auth, анонимизация, оркестрация RAG↔LLM, экcпорт |
| **RAG-сервис** | **Python** (FastAPI) | Чанкинг, эмбеддинги, retrieval, промпт, ingestion |
| **PostgreSQL** | Postgres 16 | Пользователи, сессии, история (без ПДн) |
| **Qdrant** | Qdrant | Векторы чанков + метаданные |
| **LLM** | X5 CoPilot API | Генерация текста (обезличенный промпт) |

### 3.2. Обоснование выбора Go

Go выбран не «для галочки», а для задач, где он **объективно лучший инструмент**:

1. **Анонимизация — критический барьер данных.** Go обеспечивает строгую статическую типизацию (меньше ошибок в коде, отвечающем за приватность детей), высокую производительность потоковой обработки текста (regex, сканеры, пайплайны), простую конкурентность (goroutines) для параллельных детекторов.

2. **API-Gateway / оркестратор — классическая ниша Go.** Конкурентные сетевые сервисы, тайм-ауты, ретраи, fallback между моделями LLM, агрегация ответов. На Go написаны Docker, Kubernetes, Traefik — это проверенная технология для подобных задач.

3. **Экспорт документов — CPU-bound генерация.** Прямая сборка OOXML (Word) и PDF через `archive/zip` и `encoding/xml`, без внешних библиотек.

4. **Аутентификация на stdlib.** JWT на `crypto/hmac` + `crypto/sha256` (без сторонних библиотек), Argon2id через `golang.org/x/crypto` — демонстрация владения Go-stdlib.

5. **Безопасность по умолчанию.** Один статически слинкованный бинарь, минимальный контейнер, малая поверхность атаки — золотой стандарт для компонента, работающего с персональными данными.

### 3.3. Обоснование выбора Python для RAG

Python выбран для ML-части RAG-пайплайна, где экосистема не имеет альтернатив:

- `sentence-transformers` — локальные эмбеддинги (multilingual-e5-large);
- `fastembed` / `qdrant_client` — нативная интеграция с Qdrant;
- зрелые библиотеки для chunking, text extraction (`.docx`, `.odt`);
- быстрая итерация для экспериментов с промптами и retrieval-стратегиями.

**Разделение труда честно и обоснованно:** Go — безопасность, скорость, надёжность на «передаче»; Python — ML и экосистема для интеллектуальной части.

### 3.4. Выбор Qdrant

| Критерий | Qdrant | pgvector | Chroma |
|---|---|---|---|
| Open-source, бесплатно | ✅ | ✅ | ✅ |
| Векторный поиск с payload filtering | ✅ мощная | базовая | базовая |
| Запуск в Docker | ✅ отдельный контейнер | расширение Postgres | ✅ |
| Зрелость для production | ✅ | ✅ | прототип |
| Нет внешних API-ключей | ✅ | ✅ | ✅ |

**Выбор: Qdrant** — лучшая open-source специализированная векторная СУБД с продвинутой фильтрацией по метаданным (тип документа, синдром, класс диагноза), что критично для медицинского RAG.

### 3.5. MCP-сервер (архитектурное решение)

**MCP (Model Context Protocol)** — протокол Anthropic для стандартизации доступа внешних ИИ-агентов к инструментам. Для ядра MVP поток управляется самим приложением, а не внешним агентом, поэтому MCP-сервер не стоит на критическом пути.

Вместо этого Go распределён на более честную и сильную роль (Gateway + анонимизация + экспорт), а MCP-обёртка над сервисом анонимизации предусмотрена как **опциональный архитектурный элемент** для будущей интеграции с внешними ИИ-агентами (например, Claude Desktop).

## 4. RAG-система: от корпуса к дневнику

### 4.1. RAG — что это и зачем

**RAG (Retrieval-Augmented Generation)** — архитектура, при которой LLM перед генерацией получает **релевантные примеры из реального корпуса** документов. Это принципиально отличается от «просто ChatGPT»:

| Аспект | «Просто ChatGPT» | PsyNote с RAG |
|---|---|---|
| Источник стиля | Общие знания модели | Корпус реальных дневников отделения |
| Точность формулировок | Произвольная | Соответствует стандартам отделения |
| Клиническая специфика | Общие медицинские термины | Конкретные формулировки, МКБ-коды, препараты |
| Воспроизводимость | Низкая | Высокая (одни и те же образцы → стабильный стиль) |
| Юридическая корректность | Не гарантирована | По шаблонам реальных документов |
| Галлюцинации | Вероятны | Минимизированы (модель опирается на фактические примеры) |

### 4.2. Пайплайн ingestion (загрузка корпуса)

```
Файл (.docx/.odt)
  → Извлечение текста
    → Анонимизация (Go-сервис, гейт)
      → Валидация: ПДн отсутствуют?
        → ДА: Чанкинг (структурный) + метаданные
          → Эмбеддинги (sentence-transformers, локально)
            → Upsert в Qdrant
        → НЕТ: Документ отклонён (карантин)
```

**Ключевой принцип:** анонимизация происходит **до** любого хранения — ни векторы, ни метаданные, ни сам текст не содержат персональных данных.

### 4.3. Чанкинг медицинских документов

Дневники имеют **чёткую структуру**. Чанкинг — структурно-осознанный, а не «слепое нарезание по N символов»:

- **Ежедневная запись** → один чанк (дата + психический статус + соматика + подпись).
- **Расширенный осмотр** → разбивается по секциям (Жалобы, Анамнез, Психический статус, Диагноз, Назначения, Этапный эпикриз).

**Метаданные каждого чанка** (для фильтрации в Qdrant):

| Поле | Примеры |
|---|---|
| `doc_type` | `daily` / `exam_10d` |
| `section` | `psych_status` / `somatic` / `epicrisis` / `full` |
| `syndrome` | `тревожно-депрессивный` / `психопатоподобный` |
| `diagnosis_class` | `F9x` / `F06` (верхний уровень МКБ) |
| `dynamics` | `улучшение` / `без динамики` / `ухудшение` |

### 4.4. Retrieval-стратегия

При запросе врача система выполняет **многоступенчатый поиск**:

1. **L0 фильтр** — по метаданным: `doc_type` + `syndrome` + `diagnosis_class` (если указаны).
2. **Семантический поиск** — вычисление эмбеддинга запроса (локально, multilingual-e5-large) + поиск ближайших векторов в Qdrant.
3. **MMR (Maximal Marginal Relevance)** — обеспечение разнообразия результатов (не все 5 примеров от одного пациента).
4. **Ранжирование** — приоритет по релевантности и разнообразию метаданных.
5. **Формирование контекста** — top-k (4–6) чанков включаются в промпт как few-shot примеры.

**Преимущество Qdrant:** поиск не «просто похожее», а «похожее нужного типа и регистра»: для ежедневного дневника — примеры ежедневных записей, для осмотра — примеры осмотров.

### 4.5. Промпт-инжиниринг

Структура финального промпта:

```
[SYSTEM]
Ты — ассистент детского врача-психиатра. Пишешь медицинские дневники
строго в стиле и терминологии отделения. Не выдумывай факты.
Используй только предоставленные данные. Соблюдай структуру шаблона.
Пиши на русском, сохраняй МКБ-коды и латинские названия препаратов.
НИКОГДА не вставляй реальные ФИО, даты рождения, адреса.

[CONTEXT: ШАБЛОН]
<структура разделов нужного типа документа>

[CONTEXT: ОБРАЗЦЫ ИЗ КОРПУСА (обезличенные, top-k)]
<пример 1: ежедневный дневник ~минут>
<пример 2: ежедневный дневник ~минут>
...

[USER: ОТВЕТЫ ОПРОСНИКА]
Тип: ежедневный дневник
Динамика: без существенных изменений
Настроение снижено; отмечаются тревога, плаксивость
Сон: трудности засыпания. Аппетит снижен
Терапию переносит хорошо. Жалоб активно не предъявляет.
```

**Принципы промпт-инжиниринга:**
- **Низкая температура** (0.3–0.5) — предсказуемость и юридическая аккуратность, а не творчество.
- **Anti-hallucination** — явный запрет выдумывать факты, только данные опросника + образцы.
- **Плейсхолдеры вместо ПДн** — `[ДАТА]`, `[ФИО ВРАЧА]` — врач подставляет при экспорте.
- **Вариативность** — просьба варьировать формулировки, чтобы соседние записи не были дословными копиями.

## 5. Анонимизация: защита персональных данных

### 5.1. Принцип «гейта» (Gate-First)

Анонимизация — **не опция, а барьер на воротах**. Любые данные проходят через анонимизатор **до** записи в PostgreSQL, до записи в Qdrant, до отправки в LLM, до записи в любой лог.

### 5.2. Многоуровневый пайплайн (Defense in Depth)

Один метод ненадёжен. Система использует **несколько независимых уровней**, каждый ловит то, что пропустил предыдущий:

| Уровень | Метод | Что ловит |
|---|---|---|
| **1. Нормализация** | Unicode, пробелы, извлечение из `.docx`/`.odt` | Подготовка текста |
| **2. Regex-детекторы** | Паттерны дат, телефонов, адресов, номеров документов, СНИЛС/паспорт/полис | Структурированные ПДн |
| **3. Словари (Gazetteers)** | 13 000+ русских имён, 47 000+ фамилий, названия медучреждений, ФИО медперсонала | Known-entities |
| **4. Морфология ФИО** | Склонения фамилий (Гаврилов/Гаврилова/Гаврилову), суффиксы отчеств (-вич/-вна) | Падежные формы |
| **5. Whitelist-защита** | МКБ-коды (`F92.8`), латинские названия препаратов, дозировки, аббревиатуры статусов | Сохранение клинической ценности |
| **6. Валидатор-гейт** | Повторный независимый проход «параноидальными» детекторами | Остаточные ПДн |

### 5.3. Fail-closed архитектура

```
Входной текст → Анонимизация (уровни 1–5)
  → Валидатор-гейт: ПДн отсутствуют?
    → ДА: обезличенный текст → БД / Qdrant / LLM
    → НЕТ: БЛОКИРОВКА → 422 ошибку, данные НЕ попадают никуда
```

**Ключевое правило:** если после анонимизации валидатор всё ещё подозревает ПДн — система **блокирует**, а не «пропускает на свой страх». Лучше отказать, чем допустить утечку.

### 5.4. Стратегия замены: типизированные плейсхолдеры

Заменяем не на единый `[УДАЛЕНО]`, а на **типизированные плейсхолдеры** — это сохраняет смысл для генерации:

| Сущность | Плейсхолдер |
|---|---|
| ФИО пациента | `[ПАЦИЕНТ]` |
| ФИО врача | `[ФИО_ВРАЧА]` |
| Дата | `[ДАТА]` |
| Возраст | `[ВОЗРАСТ]` |
| Адрес | `[АДРЕС]` |
| Учреждение | `[УЧРЕЖДЕНИЕ]` |
| Номер документа | `[НОМЕР_ДОКУМЕНТА]` |

### 5.5. Необратимость: осознанный выбор

- В БД и Qdrant **только необратимо обезличенный текст**.
- Карта «плейсхолдер → реальное значение» на сервере **не хранится**.
- Реальные данные существуют **только** в оперативной памяти во время обработки запроса и **стираются** после ответа.
- Псевдонимизация с обратимым ключом **сознательно отвергнута** — лишний риск утечки.

### 5.6. Сводка обезличивания

Система логирует **только количество** обезличенных сущностей по категориям (без самих значений):

```
anonymized: fio=3, dates=5, addresses=1, institutions=2, doc_numbers=1
```

## 6. Динамический опросник: UX врача

### 6.1. Принцип: структурированный ввод вместо свободного текста

Врач **не пишет текст вручную** и **не ведёт свободный чат**. Вместо этого он проходит короткий опросник с вариантами ответов.

**Принципы дизайна:**
1. 5–10 базовых вопросов, покрывающих то, что меняется день ото дня.
2. Постоянные данные (физикальный статус в норме) подставляются по умолчанию.
3. Дефолты — по наблюдениям корпуса (самые частые формулировки в реальных дневниках).
4. Каждый дропдаун содержит опцию «Свой вариант» с возможностью ввода нескольких кастомных чипов.
5. Ответы несут `prompt`-строку для формы — система автоматически маппит выбор врача в клинические формулировки.

### 6.2. Условные (каскадные) вопросы

Дерево опросника содержит **зависимые вопросы**, которые появляются только при определённых ответах. Это минимизирует визуальный шум и ускоряет заполнение:

```
Q3: Фон настроения → снижен/неустойчив?
  → Q3a: Детали настроения [тревога, плаксивость, раздражительность...]
  
Q6: Сон → нарушен?
  → Q6a: Характер нарушения [трудности засыпания, пробуждения...]

Q8: Переносимость терапии → нежелательные явления?
  → Q8a: Какие явления [свободный ввод]

Q9: Жалобы → есть?
  → Q9a: Какие жалобы [частые варианты + свой ввод]
```

### 6.3. Пример экономии времени

**Без PsyNote (20 минут, вручную):**
> Врач формулирует текст: «Сознание ясное. Ориентирован верно. Контакт доступен, на вопросы отвечает по существу. Фон настроения снижен, отмечается тревога, плаксивость. Поведение упорядочено, режим соблюдает. Сон нарушен: трудности засыпания. Аппетит снижен. Терапию переносит хорошо. Жалоб активно не предъявляет. Психопродуктивная симптоматика не выявлена.»

**С PsyNote (2–3 минуты):**
> Врач выбирает: Динамика = «без изменений», Настроение = «снижен» → [тревога, плаксивость], Сон = «трудности засыпания», Аппетит = «снижен», остальное — дефолты. Нажимает «Сгенерировать».

Результат — тот же клинически корректный текст, сгенерированный в стилистике отделения.

### 6.4. Расширяемость

Для нового типа документа (первичный осмотр, анамнез, выписной эпикриз) добавляется:
1. Запись в `document_type`.
2. Новая схема опросника (JSON).
3. Промпт-шаблон с новой структурой.

Ядро (движок опросника, анонимизатор, генерация, экспорт) **не меняется**.

## 7. Безопасность: аутентификация и изоляция

### 7.1. Аутентификация: Argon2id + JWT

Реализована **собственная система аутентификации на Go** — осознанный выбор вместо промышленного IdP (Keycloak/Authentik):

| Компонент | Реализация | Обоснование |
|---|---|---|
| Хэширование паролей | **Argon2id** (`golang.org/x/crypto`) | Текущий рекомендованный OWASP алгоритм, победитель Password Hashing Competition |
| Access-токен | **JWT HS256** (stdlib `crypto/hmac` + `crypto/sha256`) | Без внешних библиотек — демонстрация знаний Go |
| Refresh-токен | **Opaque** (случайная строка), хранится в httpOnly cookie | Ротация + отзыв через `session.revoked` в PostgreSQL |
| Изоляция | Все запросы фильтруются по `doctor_id` из JWT | На уровне репозитория, не только UI |

**Почему своя реализация, а не Keycloak:**
1. Требования простые (2 роли, без 2FA) — промышленный IdP избыточен.
2. Демонстрирует владение Go-stdlib (критично для диплома).
3. Минимум зависимостей, легко в Docker.
4. Всё локально, без внешних зависимостей.

### 7.2. Доктор-скоупинг (изоляция данных)

```
Врач A (id=7) → история — только WHERE doctor_id = 7
Врач B (id=12) → история — только WHERE doctor_id = 12
Прямой доступ по request_id → проверка владельца (иначе 403/404)
```

Глобальные выборки истории без владельца **запрещены**.

### 7.3. Ролевая модель

| Роль | Возможности |
|---|---|
| `doctor` | Генерация дневников, просмотр своей истории, экспорт |
| `admin` | Всё то же + загрузка документов в корпус, управление |

### 7.4. Threat Model (STRIDE)

| Угроза | Митигизация |
|---|---|
| Spoofing (подделка пользователя) | JWT-подпись + проверка `exp` + refresh с отзывом |
| Tampering (подмена запроса) | Подписанные JWT + HTTPS + валидация входных данных |
| Repudiation (отрицание действия) | Аудит по `doctor_id` (без ПДн) |
| Information Disclosure (утечка ПДн) | **Гейт анонимизации** + локальная обработка + логи без ПДн + изоляция по врачу |
| Denial of Service | Rate-limit на `/generate` + тайм-ауты |
| Elevation of Privilege | Проверка владельца + проверка роли `admin` |

## 8. Go-компоненты: что написано на Go и почему

Это ключевой раздел для экзамена по Golang — демонстрация владения языком, стандартной библиотекой и идиоматичным Go-кодом.

### 8.1. Сводная таблица Go-компонентов

| Компонент | Пакет | Что реализовано | Go-конструкции |
|---|---|---|---|

| **Анонимизатор** | `internal/anonymizer` | Regex-детекторы, словари 60K+, entity extraction, textutil, gate | `regexp`, `strings`, `bufio`, goroutines |

| **Config** | `internal/config` | Загрузка из env, валидация | `os`, `strconv`, `time` |

### 8.2. Ключевые Go-идиомы в проекте

**Горутины и каналы:**
- Параллельные вызовы RAG и LLM при оркестрации генерации.
- Graceful shutdown: `context.WithCancel` + `signal.Notify` + `server.Shutdown`.
- Timeout propagation через `context.WithTimeout` на каждом запросе.

**Table-driven тесты:**
```go
tests := []struct {
    name    string
    input   string
    want    string
    wantErr bool
}{...}
for _, tt := range tests {
    t.Run(tt.name, func(t *testing.T) {...})
}
```

Тесты покрывают: анонимизатор (`anonymizer_test.go`, `stage31_test.go`, `stage32_test.go`), JWT (`jwt_test.go`), пароли (`password_test.go`), экспорт (`export_test.go`, `format_test.go`), handlers (`generate_test.go`, `history_test.go`, `admin_test.go`, `anonimize_test.go`, `export_test.go`, `auth_test.go`), catalog (`catalog_test.go`), RAG-клиент (`ragclient_test.go`).

**Прямой OOXML без библиотек:**
Файл `.docx` — это ZIP-архив с XML. Go собирает его напрямую через `archive/zip` + `encoding/xml`, создавая `document.xml`, `styles.xml`, `[Content_Types].xml` с полным контролем над форматированием без внешних зависимостей.

**go:embed для шрифтов:**
```go
//go:embed fonts/DejaVuSansCondensed.ttf
var dejavuRegular []byte
```
Шрифты DejaVu с кириллицей встраиваются в бинарь на этапе компиляции — не нужно распространять файлы шрифтов.

### 8.3. Тестирование на Go

| Тип теста | Что покрыто |
|---|---|
| Unit-тесты детекторов анонимизации | Regex-паттерны, словари, падежи ФИО, диапазоны дат |
| Table-driven тесты JWT | Подпись, верификация, expired claims, невалидный токен |
| Тесты Argon2id | Хэширование, верификация, некорректный формат |
| Тесты экспорта | Форматирование дневников, сборка DOCX/PDF |
| Тесты handlers | API-эндпоинты через httptest |
| Тесты RAG-клиента | HTTP-моки, обработка ошибок |

## 11. Demo-сценарий для защиты

### 11.1. План демонстрации (5–7 минут)

| Шаг | Действие | Что показываем |
|---|---|---|
| **1. Регистрация** | Открыть `/auth`, создать аккаунт врача | Работающая аутентификация (Argon2id + JWT). Показать httpOnly cookie в DevTools |
| **2. Вход** | Логин → попадаем на главную (опросник) | JWT access-токен, doctor-scoping |
| **3. Опросник** | Заполнить ежедневный дневник: выбрать «Настроение: снижен» → появляется Q3a (детали); выбрать «Сон: нарушен» → появляется Q6a | Каскадные условные вопросы, «свой вариант», дефолты |
| **4. Генерация** | Нажать «Сгенерировать» | RAG-пайплайн: анонимизация → retrieval → LLM → готовый дневник. Показать, что генерация идёт по шаблону отделения |

| **7. Админка** | Загрузить документ → анонимизация → ingestion в Qdrant | Полный цикл расширения корпуса |

### 11.2. Ключевые тезисы для выступления

> **Проблема:** Детский психиатр тратит до 10 часов в день на шаблонную документацию. PsyNote сокращает это до 1.5–2 часов.

> **Технологии:** Go — защитный периметр: анонимизация, аутентификация, оркестрация, экспорт. Python — RAG: векторный поиск + промпт-инжиниринг. Docker Compose — один деплой.

> **RAG ≠ ChatGPT:** Система опирается на реальные клинические документы отделения, а не на «общие знания» модели. Результат — узнаваемый стиль, юридическая корректность, отсутствие галлюцинаций.

> **Безопасность:** Ни одно ФИО, дата, адрес не хранится в БД. Многоуровневая анонимизация с fail-closed политикой. JWT на Go-stdlib, Argon2id, doctor-scoping.

> **Go — честная роль:** Анонимизатор на Go (строгая типизация + скорость + конкурентность), JWT stdlib (демонстрация знаний), экспорт .docx (.docx = ZIP + XML — прямая сборка на Go без библиотек).

## 12. Развитие проекта

Проект спроектирован как **расширяемая платформа**, а не одноразовый диплом:

- **Архитектура** позволяет добавлять новые типы документов без изменения ядра.
- **RAG-пайплайн** масштабируется на новые корпуса и отделения.
- **Go-сервисы** декомпозированы по ответственности и могут расти независимо.
- **Анонимизация** единая для рантайма и ingestion — одни гарантии везде.
- **MCP-фасад** готов к реализации как вишенка на торте.

Система **production-ready** в рамках описанных требований и готова к пилотному внедрению в реальном отделении детской психиатрии.
